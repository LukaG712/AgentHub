# Agent Hub — HTTP API Reference

All API endpoints live under `/api/` and require Bearer token authentication.  The static web dashboard at `/` does not require auth.

## Authentication

Every request to `/api/*` must include the header:

```
Authorization: Bearer <HUB_API_KEY>
```

The key is set in the `.env` file (generated by `setup.sh`) or via the `HUB_API_KEY` environment variable.  A missing or invalid token returns `401 Unauthorized`.

## Status

### Get overall status

```
GET /api/status
```

Returns the state of every agent (working, idle, or failed), the queue length, provider availability, and configuration issues.

**Response:**
```json
{
  "agents": [
    {
      "name": "vault",
      "state": "idle",
      "queue_length": 0,
      "last_run": { "id": "...", "state": "done", "task": "..." }
    }
  ],
  "providers": [
    { "name": "junie", "available": true }
  ],
  "issues": [
    { "agent": "vault", "severity": "warning", "message": "Project directory does not exist: /mnt/vault" }
  ],
  "healthy": true
}
```

`healthy` is `false` if any agent has an error-level issue (e.g., provider not registered). Warnings (missing project directory, provider binary not found) do not affect health.

**Response:**

{
  "providers": [

## Agents

### List all agents

```
GET /api/agents
```

**Response:**
```json
{
  "agents": [
    {
      "name": "vault",
      "title": "Vault librarian",
      "description": "Reads and updates the Obsidian vault notes.",
      "runner": "junie",
      "project_dir": "/mnt/vault",
      "skills": ["vault-conventions"],
      "guidelines": "Never delete files.",
      "permissions": {
        "file_read": true,
        "file_write": true,
        "command_exec": true,
        "git_ops": true,
        "network": true
      }
    }
  ]
}
```

`permissions` is optional. When omitted, all permissions default to `true`.

### Get a single agent

```
GET /api/agents/{name}
```

**Response:** Same shape as one entry in the list above.

**Error:** `404` if the agent doesn't exist.

### Create an agent

```
POST /api/agents/{name}
```

**Request body:**
```json
{
  "runner": "junie",
  "project_dir": "/path/to/project",
  "title": "My agent",
  "description": "Does something useful",
  "skills": [],
  "guidelines": "Be helpful.",
  "permissions": {
    "file_read": true,
    "file_write": true,
    "command_exec": true,
    "git_ops": true,
    "network": true
  }
}
```

`project_dir` and `runner` are required.  `runner` must match a registered provider name.  `permissions` is optional — when omitted, all permissions default to `true`.

**Response:** `201` with the created agent object.

**Error:** `400` if the name is invalid or `project_dir` is missing.

### Update an agent

```
PUT /api/agents/{name}
```

**Request body:** Any subset of editable fields:
```json
{
  "title": "Updated title",
  "project_dir": "/new/path",
  "skills": ["new-skill"],
  "guidelines": "New guidelines."
}
```

Editable fields: `title`, `description`, `runner`, `project_dir`, `skills`, `guidelines`.  Runner command templates cannot be changed through the API.

**Response:** Updated agent object.

**Error:** `404` if the agent doesn't exist.

### Delete an agent

```
DELETE /api/agents/{name}
```

**Response:**
```json
{ "deleted": "vault" }
```

**Error:** `404` if the agent doesn't exist.

## Runs

### Start a run (dispatch a task)

```
POST /api/agents/{name}/runs
```

**Request body:**
```json
{
  "task": "Summarize the notes in _ai/ folder"
}
```

`task` is required.  The run starts in the background; the response returns immediately.

**Response:** `201`
```json
{
  "status": "queued",
  "agent": "vault",
  "task": "Summarize the notes in _ai/ folder"
}
```

**Error:** `404` if the agent doesn't exist, `400` if `task` is missing.

### List runs

```
GET /api/runs?agent=vault&state=done
```

Query parameters (both optional):
- `agent` — filter by agent name
- `state` — filter by state (`queued`, `working`, `done`, `failed`, `stopped`)

**Response:**
```json
{
  "runs": [
    {
      "id": "abc-123",
      "agent": "vault",
      "task": "Summarize notes",
      "state": "done",
      "started": "2026-10-18T12:00:00",
      "finished": "2026-10-18T12:01:30",
      "exit_code": 0,
      "answer": "The notes cover...",
      "log_file": "data/runs/vault/abc-123.log",
      "raw_output": "...",
      "owner_pid": 1234,
      "pid": null,
      "pgid": null,
      "fail_reason": null
    }
  ]
}
```

### Get a single run

```
GET /api/runs/{run_id}
```

**Response:** One run object (same shape as above).

**Error:** `404` if the run ID doesn't exist.

### Stop a run

```
POST /api/runs/{run_id}/stop
```

Stops a running agent by killing its process group.  If the run is already finished or the process was reused, the run is marked as stale instead.

**Response:** Updated run object with `state: "stopped"`.

**Error:** `404` if the run ID doesn't exist.

## Skills

### List all skills

```
GET /api/skills
```

**Response:**
```json
{
  "skills": [
    {
      "name": "vault-conventions",
      "description": "Obsidian vault naming rules",
      "used_by": ["vault"]
    }
  ]
}
```

### Get a single skill

```
GET /api/skills/{name}
```

**Response:**
```json
{
  "name": "vault-conventions",
  "content": "---\nname: vault-conventions\n...\n---\n\nSkill content...",
  "used_by": ["vault"]
}
```

**Error:** `404` if the skill doesn't exist.

### Create a skill

```
POST /api/skills/{name}
```

**Request body:**
```json
{
  "content": "---\nname: my-skill\ndescription: Does something\n---\n\nSkill body...",
  "description": "Does something"
}
```

`content` should be the full SKILL.md text including YAML frontmatter.

**Response:** `201` with the created skill object.

**Error:** `400` if the name is invalid or a skill with that name already exists.

### Update a skill

```
PUT /api/skills/{name}
```

**Request body:** Same as create.  Replaces the skill's content.

**Response:** Updated skill object.

**Error:** `404` if the skill doesn't exist.

### Delete a skill

```
DELETE /api/skills/{name}
```

**Response:**
```json
{ "deleted": "my-skill" }
```

**Error:** `404` if the skill doesn't exist.

## Agent ↔ Skill (Enable / Disable)

### Enable a skill for an agent

```
POST /api/agents/{agent}/skills/{skill}
```

Adds the skill to the agent's enabled list and syncs symlinks.

**Response:**
```json
{ "agent": "vault", "skill": "vault-conventions", "enabled": true }
```

**Error:** `404` if the agent or skill doesn't exist.

### Disable a skill for an agent

```
DELETE /api/agents/{agent}/skills/{skill}
```

Removes the skill from the agent and cleans up the symlink.

**Response:**
```json
{ "agent": "vault", "skill": "vault-conventions", "enabled": false }
```

**Error:** `404` if the agent or skill doesn't exist.

## Ollama (Optional)

Ollama integration provides prompt refinement, summarization, and task decomposition. Configure it in `hub.yaml` under the `ollama` section.

### Check Ollama status

```
GET /api/ollama/status
```

**Response:**
```json
{
  "enabled": true,
  "available": true,
  "base_url": "http://localhost:11434",
  "model": "llama3"
}
```

Returns `enabled: false` when Ollama is not configured in `hub.yaml`.

### Refine a prompt

```
POST /api/ollama/refine
```

**Request body:**
```json
{
  "prompt": "Fix the bug",
  "context": "Optional project context",
  "system_instruction": "Optional custom instruction"
}
```

`prompt` is required. `context` and `system_instruction` are optional.

**Response:**
```json
{
  "original": "Fix the bug",
  "refined": "Fix the authentication bug by adding null checks",
  "changed": true
}
```

**Error:** `400` if Ollama is not configured or `prompt` is missing.

### Summarize text

```
POST /api/ollama/summarize
```

**Request body:**
```json
{
  "text": "Long text to summarize...",
  "max_length": 500,
  "focus": "errors"
}
```

`text` is required. `max_length` defaults to 500. `focus` is optional.

**Response:**
```json
{
  "summary": "The agent encountered three errors..."
}
```

**Error:** `400` if Ollama is not configured or `text` is missing.

### Decompose a task

```
POST /api/ollama/decompose
```

**Request body:**
```json
{
  "task": "Build a new feature",
  "context": "Optional context"
}
```

`task` is required.

**Response:**
```json
{
  "subtasks": [
    {"step": "1", "description": "Plan the feature", "dependencies": []},
    {"step": "2", "description": "Implement core logic", "dependencies": ["1"]}
  ]
}
```

**Error:** `400` if Ollama is not configured or `task` is missing.

## Obsidian (Optional)

Obsidian integration allows reading notes and writing session summaries. Configure it in `hub.yaml` under the `obsidian` section.

### Check Obsidian status

```
GET /api/obsidian/status
```

**Response:**
```json
{
  "enabled": true,
  "available": true,
  "vault_path": "/path/to/vault"
}
```

### List notes

```
GET /api/obsidian/notes?q=search&tag=tag&folder=folder&limit=50
```

All query parameters are optional.

**Response:**
```json
{
  "notes": [
    {
      "id": "note-id",
      "title": "Note Title",
      "path": "folder/note.md",
      "tags": ["tag1"],
      "created_at": "2026-01-01T00:00:00",
      "modified_at": "2026-01-01T00:00:00"
    }
  ]
}
```

### Get note content

```
GET /api/obsidian/notes/{note_id}
```

**Response:**
```json
{
  "id": "note-id",
  "title": "Note Title",
  "path": "folder/note.md",
  "content": "# Note Title\n\nContent..."
}
```

### Sync session to Obsidian

```
POST /api/obsidian/sync
```

**Request body:**
```json
{
  "session_id": "session-uuid"
}
```

**Response:** `201` with the created note object.

**Error:** `400` if Obsidian is not configured, `404` if session not found.

## Example: Full workflow

Start a task and poll until it finishes:

```bash
# 1. Dispatch a run
curl -X POST http://localhost:8080/api/agents/vault/runs \
  -H "Authorization: Bearer $HUB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"task": "List all notes in _ai/"}'

# Response: {"status": "queued", "agent": "vault", "task": "List all notes in _ai/"}

# 2. Find the latest run for this agent
curl http://localhost:8080/api/runs?agent=vault \
  -H "Authorization: Bearer $HUB_API_KEY"

# Note the "id" field from the first result

# 3. Poll the run status
curl http://localhost:8080/api/runs/<run-id> \
  -H "Authorization: Bearer $HUB_API_KEY"

# Repeat until state is "done", "failed", or "stopped"
```
